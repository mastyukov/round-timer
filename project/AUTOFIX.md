# Round Timer — бесплатный AI QA с ChatGPT Automations

**Статус:** кандидат в изолированной ветке `setup/diagnostic-monitor-3d`. Рабочий код v0.8.5 не изменён. Платный Codex GitHub Action удалён.

## Контур работы

1. GitHub Actions раз в три дня запрашивает Cloudflare Analytics Engine. Читает **только** количество технических ошибок за 72 часа, сгруппированное по четырём кодовым полям.
2. Новые коды ошибок становятся внутренними GitHub Issues с меткой `round-timer-diagnostics`, **без упоминаний владельца**. Повторные коды добавляются к существующим Issue, не создавая дубликатов.
3. ChatGPT Automations с трёхдневным интервалом, начиная с 11 ноября 2026 года, 22:30 МСК, рассматривает Issues через подключённый GitHub. Этот шаг работает в рамках текущего доступа ChatGPT, **без OPENAI_API_KEY**.
4. Если причина достоверно воспроизводится и безопасно исправима, ChatGPT может подготовить изменение в отдельной ветке `assistant/round-timer/*`. Разрешены только существующие файлы `site/app.mjs`, `site/engine.mjs`, `site/sw.js`, `site/diagnostics/*.mjs` и `tests/*.test.mjs`. Никакой реальной пользовательской информации.
5. GitHub CI для этих веток проверяет синтаксис, JS-тесты и Python-тесты. **Только фактически успешный CI** позволяет говорить о проверенном кандидате.
6. После независимой проверки изменений ChatGPT готовит draft PR, не объединяя его и не публикуя сайт. Лишь тогда уведомляет владельца и просит разрешение на публикацию.
7. Если ошибка не воспроизводится, GitHub недоступен или CI не прошёл — никакого сообщения «исправление готово» и никакого релиза.

## Ограничения и правдивые статусы

- Регулярная задача создана, но первое выполнение по расписанию и настоящий AI-кодовый цикл **ещё не подтверждены**. Нет гарантии, что среда очередного запуска ChatGPT сможет воспользоваться всеми инструментами GitHub. При недоступности инструмента автоматизация не должна утверждать, что исправила ошибку.
- У ChatGPT Plus есть лимиты использования. Отдельного счёта за API в этом варианте не требуется.
- Автоматическое исправление по одному коду иногда невозможно. Количество событий — не количество отдельных пользователей.
- Скрытого доступа к iPhone нет; UI/звуки/офлайн на реальном телефоне не доказываются одними автоматическими тестами.
- GitHub Actions не запускает Codex и не получает секреты OpenAI API.
- GitHub Pages никогда не публикуется из ветки `assistant/round-timer/*`: для любого релиза нужно явное разрешение владельца и объединение в `main`.

## Проверки

- Предыдущий запуск до удаления платного этапа: 21/21 Python unit-тестов PASS, Cloudflare SQL PASS.
- После удаления платного этапа GitHub CI и монитор branch dry-run PASS. Изолированные ветки `assistant/round-timer/*` включены в область проверок CI.
- В подключённом GitHub на этапе подготовки не обнаружены открытые Issues с меткой `round-timer-diagnostics`; синтетический анализ не создавал пользовательских Issues и PR.
- **НЕТ PASS** для полного автономного AI-исправления: требуется подходящая воспроизводимая синтетическая ошибка, независимая проверка созданного PR и фактическая доставка уведомления.

## Включение в основную инфраструктуру

Перед включением мониторинга в `main` необходимы дополнительная проверка синтетической ошибки и **отдельное подтверждение пользователя**. До этого рабочий Round Timer не меняется.
