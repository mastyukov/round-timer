# Round Timer — автономное исправление ошибок (предложение к включению)

**Статус:** подготовлено в изолированной ветке; в main НЕ объединено; OpenAI API не подключён.

## Цель
Раз в три дня получать только агрегированные коды технических ошибок с Cloudflare. При обнаружении нового типа сбоя автоматически инициировать попытку воспроизведения и исправления через Codex в GitHub Actions. Уведомлять владельца **только при успешной подготовке кандидата исправления**, а не о каждом полученном событии.

## Цепочка
1. GitHub Actions по расписанию (11, 14, 17 ноября и далее каждый третий день) получает безопасную четырёхпольную сводку за 72 часа.
2. В GitHub создаётся внутренняя Issue без `@mention`, чтобы не беспокоить владельца. Повторные события объединяются.
3. Только по первой новой сигнатуре за один трёхдневный цикл GitHub запускает `autofix-diagnostics.yml` через `workflow_dispatch`. При отсутствии `OPENAI_API_KEY` попытка исправления не запускается.
4. Codex в GitHub Actions с правами `contents: read` анализирует **только фиксированные поля**; содержимое Issue, произвольные сообщения, IP и устройство ему не передаются. Если причина по коду не подтверждается — никаких изменений.
5. Codex вправе менять только существующие разрешённые файлы в `site/` и `tests/*.test.mjs`. Выводится небольшой patch, но не рабочий релиз.
6. Отдельная среда QA **без API-ключа и без GitHub write** проверяет patch, обязательный регрессионный тест, полный набор JS и Python тестов.
7. Только если все проверки PASS, отдельный job (без OpenAI API-ключа, без запуска изменённого кода с write-токеном) открывает PR из ветки `autofix/...`. В описании PR отмечается `@mastyukov-cyber` — это единственное штатное уведомление владельцу.
8. Изменения основного `main` и публикация пользовательского приложения возможны **только после отдельного подтверждения владельца**.

## Ограничения
- Отчёт по ошибке содержит всего четыре поля и количество повторений, не детали отдельного пользователя; этого может оказаться недостаточно для воспроизведения. Не гарантируется исправление каждого случая.
- Автоматические тесты и статический контроль не доказывают, что ошибка исправлена на всех моделях iPhone. Финальное решение владельца обязательно.
- Предел: не более **одной новой попытки Codex на трёхдневный мониторинговый цикл**.
- Не предусмотрены неограниченные циклы попыток исправления: повторные ошибки остаются в исходной Issue.
- Для работы нужен **отдельно оплачиваемый OpenAI API**. Подписка ChatGPT Plus не заменяет API-кредиты. Создать отдельный ограниченный проект/ключ `OPENAI_API_KEY` и настроить бюджет до запуска.
- Необходимо разрешить GitHub Actions создавать Pull Requests в настройках репозитория и организации. Фактическая возможность не проверена, пока не создан реальный тестовый PR.
- **Прямые уведомления в ChatGPT не настроены**; целевой канал — GitHub упоминание в готовом PR. У владельца в GitHub Notifications нужно включить уведомления об упоминаниях, но не Watch → All Activity.
- При неудаче автоматический запуск остаётся в GitHub Actions/Issues, но **не объявляется готовым исправлением**.
- Не выполнять синтетический Codex-прогон, который реально потратит API-кредиты, без утверждённого бюджета.

## Что нужно для полного включения
1. Настроить OpenAI Platform API и ограничить бюджет.
2. Сохранить секрет `OPENAI_API_KEY` в GitHub Actions Secrets непосредственно через GitHub, не передавая его в чат.
3. Проверить поведение workflow без публикации и без реальных персональных данных.
4. Получить явное подтверждение владельца на объединение в `main`.
5. Проверить первое фактическое автоматическое исправление и уведомление владельца; до этого статус не считать рабочим.
