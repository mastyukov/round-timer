# Диагностика Round Timer — технические ошибки без лишнего сбора

**Статус:** владелец 08.11.2026 утвердил реализацию автоматической отправки технических ошибок без дополнительных экранов, окон и кнопок. На момент этой контрольной точки **нет настроенного HTTPS-приёмника, отправка с пользовательских устройств не включена**.

## Собирать только при реальной технической ошибке
- `app_error`: необработанная ошибка интерфейса/JavaScript, только фиксированный код ошибки.
- `asset_error`: ошибка загрузки основного файла, только фиксированный код.
- `audio_failure`: невозможность воспроизведения нужного сигнала, только фиксированный код.

Поля: **тип ошибки, код, компонент, версия приложения**. Для анализа на сервере дата может округляться до дня. Отправлять не более пяти событий за один запуск приложения. Повторные ошибки могут агрегироваться счётчиками. Необязательная статистика использования **не нужна и запрещена текущим решением**.

Не собирать: посещения, количество тренировок, длительность, настройки, имя, телефон, email, IP в составе события, устройство по ID, историю действий, текст ошибки, stack trace, URL, геолокацию и произвольные строки. Сервер сети технически видит IP при соединении; дополнительно проверяем правила хостинга и доступа к серверным журналам.

## Интерфейс
Никаких новых окон, кнопок, попапов, баннеров, уведомлений или фонового звука. Описание обработки данных должно оставаться доступным в ненавязчивой форме (публичная страница конфиденциальности/существующий интерфейс) без скрытого отслеживания.

## Архитектура
- `diagnostics/schema.mjs` — отбрасывает лишние поля.
- `diagnostics/sender.mjs` — готовит HTTPS-запрос лишь при заданном действительном URL; без URL **не выполняет никаких сетевых операций**.
- `tests/diagnostics-sender.test.mjs` — проверяет отсутствие PII, отсутствие отправки без приёмника, запрет статистики, ограничение частоты, безопасный отказ.
- GitHub Pages не принимает POST-отчёты; нужен отдельный доступный из России HTTPS-приёмник.
- Sentry SaaS недоступен из РФ (официальные ограничения), Beget Free с одним техническим HTTP-адресом нельзя использовать из HTTPS-PWA для POST.
- Кандидат: Google Apps Script + Google Sheets, но анонимный приём и доставка из России требуют самостоятельной синтетической проверки. Провайдер ещё не выбран и не подключён.
- Отсутствие сети или отказ отчёта никогда не влияет на отсчёт времени и звуковые сигналы.
- Запрос в `no-cors` может быть отправлен, но не подтверждает доставку; необходим тест получения записи на сервере.

## Граница внедрения
1. Подтвердить надёжный HTTPS-приёмник, место хранения, ограничения объёма/сроков, доступ к журналам, отсутствие лишних персональных данных.
2. Проверить на синтетических событиях и без VPN.
3. Только после проверки интегрировать модуль в тестовую PWA и затем выпустить по разрешению владельца.
