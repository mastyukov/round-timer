# Диагностика Round Timer — проектирование, НЕ включено

## Цель
Выявлять проблемы загрузки, офлайн-кэша, воспроизведения звука, JS-ошибок и обновлений; анализировать частоту ошибок по версиям.

## Пользовательский интерфейс
**Никаких всплывающих окон во время тренировки.** Информация о диагностике — короткий пункт «Конфиденциальность» в настройках; без навязчивых модальных окон. Необязательная аналитика включается только по добровольному действию пользователя.

## Минимальный набор событий (проект)
- `app_error`: код ошибки из закрытого справочника, версия сборки, тип компонента (UI/audio/cache).
- `asset_error`: тип ресурса, локальный/сетевой этап, статус без URL с query.
- `offline_fallback`: успешное/неуспешное использование локального кэша (если событие можно зарегистрировать).
- `audio_failure`: код ошибки звукового воспроизведения и тип сигнала.

Статистика `session_start`, `workout_start`, `workout_complete` — отдельная **необязательная** аналитика, по умолчанию выключена.

## Запрещённые поля
Имена, телефоны, email, GPS, точные IP-адреса, рекламные ID, persistent device ID, fingerprint, исходный User-Agent, текст свободного ввода, снимки экрана, аудио, полные URL, cookie, персональные данные детей.

## Передача и хранение
- GitHub Pages — статический хостинг; он **не принимает** логи как собственное API.
- Поставщик приёма, правила хранения, доступность из России и обработка IP на сервере ещё НЕ выбраны/НЕ проверены.
- Логи можно локально буферизовать ограниченно, не мешая офлайн-работе, но автоматическую сетевую отправку **не включать**, пока не проработана прозрачность для пользователей и необходимое согласие.
- Никаких технических токенов в JavaScript. В GitHub публикуются только синтетические тестовые журналы и агрегированные QA-отчёты, без пользовательских событий.

## Контроль перед внедрением
QA: офлайн, отказ сети, отключение аналитики, предел очереди, удаление локальных данных, отсутствие событий по умолчанию, невозможность извлечь персональные данные.
SECURITY: проверка отправки, сервера, утечек токенов, сроков хранения и законности сбора.
Результат: только после подтверждения владельца выпустить новую версию PWA.
