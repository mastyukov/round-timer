## Проект v0.8.6-rc1 — **НЕ РАЗВЁРНУТ**

- Только события `app_error`, `asset_error`, `audio_failure` без персональных данных.
- Очередь локально: максимум **5 записей**, суммарный сериализованный размер до **2048 байт**, хранение **до 24 часов**, максимум **4 сетевые попытки** на запись. Интервалы после неудач: 30 секунд, 2 минуты, 10 минут и затем до часа. Повтор после восстановления соединения или следующего открытия приложения — не чаще разрешённого интервала.
- При ошибке `localStorage` используется ограниченная очередь только в памяти; после закрытия вкладки она может исчезнуть. Работа и отсчёт таймера не зависят от диагностики.
- Каждая запись получает **случайный одноразовый UUIDv4**. Он относится к одной ошибке, а не к устройству или пользователю. Локально живёт максимум 24 часа; серверный ключ для подавления дублей должен истекать через 24 часа, **в Analytics Engine UUID не сохраняется**.
- Клиент использует `mode:cors`; только ответ Worker с HTTP **204**, доступный JavaScript, подтверждает обработку. Оpaque-ответ, исключение, HTTP 4xx/5xx не считаются подтверждением.
- **Важное различие:** HTTP 204 означает успешное выполнение вызова записи на стороне Worker, а не независимое доказательство появления события в Analytics Engine. Для последнего требуется отдельный агрегированный SQL-запрос.
- Worker в кандидате подавляет последовательные повторы через Cloudflare Workers KV `ERROR_DEDUP_KV`. **KV eventually consistent, поэтому полное устранение одновременных дублей не гарантируется.**
- Worker без `ERROR_DEDUP_KV` отвечает 503 для новых событий с UUID — fail closed. Старые клиенты с четырьмя полями продолжают работать. Это обеспечивает совместимость, но требует правильного порядка внедрения.

## Необходимый безопасный порядок применения

1. **Отдельно разрешить** создание пространства Cloudflare KV в рамках бесплатной квоты и binding `ERROR_DEDUP_KV`, затем проверенное развёртывание новой версии Worker без изменения PWA. Не добавлять в репозиторий секреты или реальные идентификаторы.
2. Синтетически проверить CORS, 204, повторный UUID, 503 без binding, лимиты, 429 и SQL-агрегат. Использовать **отдельный тестовый namespace/помеченные данные**, не смешивать синтетику с пользовательскими событиями. Не использовать рабочий Analytics Engine для массовых тестов.
3. Проверить кандидата на тестовом iPhone без подключённой рабочей телеметрии.
4. Только после отдельного разрешения на выпуск объединить проверенный PR в `main`, понимая, что GitHub Pages обновится автоматически.
5. При откате вернуть предыдущий `site/` (v0.8.5). Старые payload из четырёх полей новый Worker продолжает принимать.

## Платёжные и технические ограничения

Cloudflare Workers KV на бесплатном плане имеет опубликованные лимиты: **100 000 чтений и 1 000 записей в день**; превышение квоты приводит к ошибке, а не автоматической возможности превышать бесплатный лимит (см. https://developers.cloudflare.com/kv/platform/pricing/). Ключи KV не являются строгими транзакционными блокировками (https://developers.cloudflare.com/kv/concepts/how-kv-works/). Прежде чем задействовать KV, надо подтвердить текущий тариф и доступность квоты в нужном аккаунте.

**Результаты тестов:** PR №4, `tests/diagnostic-queue.test.mjs`, `tests/cloudflare-receiver.test.mjs` — только синтетические условия. Реальные подтверждения KV/CORS с iPhone до внедрения недоступны. Сообщения о недоступности не должны ломать отсчёт.

## Дополнение независимого PR №6: зависшая сеть и превью

- Отдельный сетевой запрос ограничен таймаутом **8 секунд** (возможность уменьшить в синтетических тестах). По таймауту вызывается AbortController и сохраняется *тот же* одноразовый eventId для следующей попытки после backoff. Это снижает риск бесконечной блокировки очереди, но не доказывает остановку всех слоёв реальной радиосети; при позднем ответе возможен повтор, подавляемый KV best-effort.
- Единственный одобренный origin/path отправки в производственный Cloudflare — `https://mastyukov.github.io/round-timer/` (или прямой `index.html`). Preview, localhost, CDN и зеркала отправку отключают полностью. Синтетические тесты не загрязняют рабочую статистику.
- Новый timeout/host gate: `tests/diagnostic-queue.test.mjs`, GitHub CI `42538122298` PASS; реальная сеть iPhone остаётся непроверенной.

## Итоговая модель подтверждений в независимом PR №6

- При сбое `writeDataPoint()` KV-ключ **не создаётся**, возвращается HTTP 503, а повтор с прежним eventId допускает новую попытку. Это предотвращает ложное 204 при однозначно отвергнутой записи; тестирует `tests/cloudflare-receiver.test.mjs`.
