# Round Timer — мониторинг ошибок

**Актуализировано 09.11.2026.** Live: GitHub Actions workflow находится в `main` после одобренного PR №2. Ещё **не было первого запланированного** прогона, назначенного на 11.11.2026. Состояние не путать с успешно пройденными dry-run в ветках.

## Принятые решения

Период сбора технических ошибок — **раз в три дня**: 11, 14, 17 ноября и далее с сохранением шага на границе месяца. GitHub scheduler технически запускает короткую проверку календаря ежедневно в 18:27 UTC (21:27 МСК), **Cloudflare запрашивается только в нужные даты**.

В Cloudflare SQL читаются только тип ошибки, фиксированный код, компонент, версия и агрегированный счётчик событий за 72 часа. Идентификаторы пользователей, телефонов и параметры тренировки отсутствуют. Счётчик событий не равен числу пользователей.

Новые типы ошибок создают внутренние GitHub Issues с меткой `round-timer-diagnostics`, без `@mention` владельца. Повторы обновляют существующие задачи; повторная проверка в тот же день не должна создавать копию.

ChatGPT Automation «Round Timer — бесплатный AI QA»: с 11.11.2026 в 22:30 МСК, далее каждые 3 дня. ИИ вправе готовить исправления только в изолированных ветках и сообщать владельцу **лишь о фактически проверенном кандидате**; никакой автоматической публикации. **Первое самостоятельное выполнение задачи ChatGPT и создание реального PR пока НЕ проверены**.

## Защита от молчаливого отказа системы

Отсутствие ошибок ≠ успешная проверка. При сбое Cloudflare/GitHub workflow должен завершиться FAIL. Изменение канала оповещения о таких сбоях оформлено **отдельным draft PR №5**, который нельзя включать без подтверждения владельца; он предполагает создание одной контрольной Issue с упоминанием владельца только при отказе **запланированного** мониторинга.

GitHub Actions вправе показывать свои стандартные уведомления о сбоях в зависимости от настроек аккаунта. Доставка таких сообщений на iPhone до сих пор не подтверждена.
