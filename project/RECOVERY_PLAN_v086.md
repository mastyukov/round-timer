# Round Timer — безопасное применение и откат v0.8.6-rc1

**Статус:** только предложение, НЕ выполнять автоматически. Рабочая версия `main` SHA `034ddd0c7aa1349b9f396230765ff1a8584668a0`, опубликована как v0.8.5.

## До применения

1. Зафиксировать текущие SHA каталога `site/` и контрольную точку из `main`. Убедиться, что SourceCraft и GitHub имеют проверяемую копию старой версии.
2. Поднять **отдельный test preview**, не используя рабочий Cloudflare приёмник. Убедиться, что тестовый URL реально показывает v0.8.6-rc1; старая тестовая Pages сейчас не подходит.
3. Пройти регрессионный CI (JS/Python, PWA cache), восстановление SourceCraft, WebKit/браузерную модель и короткий реальный iPhone-чек-лист.
4. Отдельно создать и проверить Cloudflare Workers KV `ERROR_DEDUP_KV` и тестовый CORS/receiver. Не вписывать в git токены, не задействовать реальные user events для тестирования.
5. Проверить совместимость нового Worker со старой 4-польной полезной нагрузкой; новый Worker развернуть **только после отдельного разрешения и серверного синтетического подтверждения**, до выпуска нового клиента.
6. Только после отдельного согласия владельца рассмотреть объединение **одного итогового PR**, не PR №4 и PR №6 независимо. Помнить, что `publish-pages.yml` автоматически публикует `site/` при изменении `main`.
7. Никакого автоматического merge/release, отключения действующих расписаний, изменения реальных данных или платного API.

## Если обнаружена проблема после выпуска

- Не изменять персональные данные пользователей (таймер их не хранит).
- Отменить выпуск путём нового подтверждённого коммита, который возвращает **точно известное содержимое каталога `site/` от v0.8.5**, затем дождаться отдельного GitHub Pages deployment PASS и проверить фактический URL/офлайн-кеш.
- Не делать force-push или удаление истории `main`. Рабочий Service Worker версии v0.8.5 снова должен активировать собственный cache, старый CacheStorage удалить лишь после полноценной установки.
- При сбое только новой диагностики можно отдельно вернуть старую клиентскую отправку и оставить старый Worker; откат Cloudflare KV/Worker осуществляется отдельно, только с разрешения владельца.
- После отката проверить на iPhone звук, время, старт/пауза, горизонталь и офлайн после первой загрузки; сохранить технические отчёты.

## Ограничение отката

Изменение Service Worker не всегда мгновенно достигает ранее установленных PWA без сети. Нельзя обещать срочный откат на каждом iPhone, пока устройство не получит обновление.

Реальные CPU/RAM и облачный трафик проверки/отката пока **не измерены**.
