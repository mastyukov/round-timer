# APP-001 — предварительное решение о публикации v0.8.6-rc1

**Дата:** 09.11.2026
**Вердикт:** **HOLD / НЕ ПУБЛИКОВАТЬ ПОКА**
**Уровень подтверждения:** фактический CI + синтетический тест + пользовательское сообщение, но **не проверена именно кандидатная версия на iPhone**.

## Доказательства для решения
- Production `main` = `034ddd0c7aa1349b9f396230765ff1a8584668a0`, опубликована v0.8.5.
- Кандидат [PR #6](https://github.com/mastyukov/round-timer/pull/6) включает изменения PR #4 и отдельные исправления сети, ACK и preview.
- [CI кандидата: 66 JS + 23 Python PASS](https://github.com/mastyukov/round-timer/actions/runs/42538292000).
- [SourceCraft: restore PASS](https://github.com/mastyukov/round-timer/actions/runs/42538292022).
- Пользователь выполнил пять шагов iPhone-чек-листа, однако **точный URL и OK/ошибка не указал**.
- Тестовый `mastyukov-cyber/round-timer-pages-test/main` содержит v0.8.5 (cache `round-timer-shell-v0.8.5-test`, диагностическая версия `0.8.5`). Публикации кандидата в отдельных ветках завершились FAIL. Пользовательский тест не является подтверждением исправленного гонга v0.8.6-rc1.
- Новый Cloudflare Worker с KV/CORS **не развёрнут**; реальные массовые запросы и равномерное подавление дублей не подтверждены.

## Предлагаемый порядок подготовки выпуска (все production-действия требуют отдельного разрешения)

1. Получить от пользователя точный адрес проверенной страницы и итог `OK` или `ОШИБКА` для пяти пунктов.
2. Отдельно согласовать **только тестовую** публикацию v0.8.6-rc1 в `mastyukov-cyber/round-timer-pages-test`. Проверить SHA развёрнутого кода и полное отключение production-диагностики для preview.
3. Провести короткий повторный iPhone-сеанс (5–10 минут) на **доказанном** preview. Особый критерий: старт → мгновенная пауза до загрузки звука → никакого запоздалого гонга.
4. Отдельно проверить Cloudflare Worker в **изолированной тестовой среде**: CORS, HTTP 204/503, одноразовые eventId, KV, повтор после потерянного ACK, отказ сервера; не отправлять синтетику в production Analytics.
5. После согласования и проверки серверной совместимости запросить отдельное разрешение на production-развёртывание Worker; клиент выпускать только после доказанной совместимости.
6. На одном итоговом release-кандидате снова запустить все тесты и контроль SHA; не объединять PR #4 и #6 независимо. Зафиксировать способ возврата `site/` к известной v0.8.5.
7. Только **после письменного подтверждения владельца** выполнять merge выбранного PR и публикацию Pages; по итогам проверить рабочий сайт и его Service Worker. Не объявлять «готово» только на основании CI.

## Запреты до следующего решения

- Никаких изменений `mastyukov/round-timer/main`, тестового репозитория `main` и Cloudflare production.
- Не объединять PR #3, #4, #5, #6, #7 без отдельного решения.
- Не считать сам факт выполнения чек-листа подтверждением успешности всех его пунктов.
- Не обещать автоматически проверенный фоновой ChatGPT AI QA до первого фактического выполнения.

**Следующее уточнение для пользователя:** какой точный URL был открыт при проверке на iPhone? После этого необходимо уточнить, были ли ошибки, и согласовать публикацию именно проверяемого кандидата в отдельный тестовый репозиторий.
